# Developing tos-recomp

How to reproduce the current state and iterate. Read `docs/m2-findings.md` first: it explains what runs, what does not, and why.

## What you need

- Your own copy of *Tales of Symphonia* for GameCube, PAL French (`GQSF`), both discs as plain `.iso`. Nothing derived from the game is ever committed: `extracted/` and `generated/` are git-ignored, and so must any screenshot or dump you make.
- Linux, GCC 13 or newer, CMake 3.20+, Ninja, SDL3 development files, OpenGL development files, `gdb` (optional).
- A checkout of the sibling repositories next to this one:

```
workspace/
  common/        https://github.com/To-Recomp/common
  gcrecomp/      https://github.com/To-Recomp/gcrecomp   (fork of sp00nznet/gcrecomp, MIT)
  tools/         https://github.com/To-Recomp/tools
  tos-recomp/    this repository
```

## 1. Extract the disc

```
cmake -S common -B common/build -G Ninja && cmake --build common/build
common/build/torecomp-disc identify tos-recomp/dumps.toml disc1.iso disc2.iso
common/build/torecomp-disc extract tos-recomp/dumps.toml disc1.iso tos-recomp/extracted/disc1
```

This verifies the dump (two levels, see `common/README.md`) and writes `sys/main.dol` and `files/`. A scrubbed dump is reported as "Compatible", which is fine.

## 2. Generate, build, run

```
tos-recomp/scripts/regen.sh      # recompiler -> generated C++ (66 MB, not committed) -> tos_boot
tos-recomp/scripts/run.sh 30     # 30 seconds, opens a window
```

`regen.sh` takes about a minute on 16 cores. A window opens on your desktop.

## 3. Symbols

`symbols/GQSF.csv` maps SDK function names to addresses and is what makes the recompiler emit named functions with native replacements. It is regenerated by `tools/sdk-identify` (see its README) from two reference games' decompilation symbol maps (Wind Waker PAL and Twilight Princess PAL, both CC0) plus `symbols/GQSF.manual.csv`, names set by hand with their evidence. `symbols/GQSF.extra_funcs.txt` lists function entries that are only reached through pointers.

A function that has a name gets, at its entry, a check for a native replacement (`lookup_os_func` in `gcrecomp/src/os/`). Adding a replacement means adding a name to one of the tables there and making sure the address is named in the CSV.

## 4. Finding out where the game is stuck

- The watchdog in `src/main.cpp` prints, when `run.sh` ends, the last indirect dispatch, the per-function counts of replaced calls (`[hle]`), and GP statistics (`[gp]`). Counts in the tens of millions point at a polling loop.
- `[FuncTable] Unresolved call to 0x...` means an indirect call to an address that is not a function entry: add the address to `symbols/GQSF.extra_funcs.txt` and run `regen.sh`.
- Attach `gdb` to the running process (`gdb -p PID -batch -ex "thread 1" -ex "bt 20"`). Generated functions are named `func_XXXXXXXX`, replaced SDK functions by their SDK name.

## 5. Conventions

- English for code, commits, issues. GPL v3 for this repository, MIT for the `gcrecomp` fork. Sign every commit (`git commit -s`): a CI check enforces it.
- Never commit game data, extracted files, generated code, or pictures of the game.
- Do not read or copy code from projects under non-commercial licenses (PolyForm Noncommercial, for example `snesrecomp`).
