# Developing tos-recomp

How to reproduce the current state and iterate. Read `docs/m2-findings.md` first: it explains what runs, what does not, and why.

## What you need

- Your own copy of *Tales of Symphonia* for GameCube, PAL French (`GQSF`), both discs as plain `.iso`. Nothing derived from the game is ever committed: `extracted/` and `generated/` are git-ignored, and so must any screenshot or dump you make.
- Linux, GCC 13 or newer, CMake 3.20+, Ninja, SDL3 development files, OpenGL development files, `gdb` (optional).
- A checkout of the sibling repositories next to this one:

```
workspace/
  common/        https://github.com/To-Recomp/common
  gcrecomp/      https://github.com/To-Recomp/gcrecomp   (fork of sp00nznet/gcrecomp, MIT)
  tools/         https://github.com/To-Recomp/tools
  tos-recomp/    this repository
```

## 1. Extract the disc

```
cmake -S common -B common/build -G Ninja && cmake --build common/build
common/build/torecomp-disc identify tos-recomp/dumps.toml disc1.iso disc2.iso
common/build/torecomp-disc extract tos-recomp/dumps.toml disc1.iso tos-recomp/extracted/disc1
```

This verifies the dump (two levels, see `common/README.md`) and writes `sys/main.dol` and `files/`. A scrubbed dump is reported as "Compatible", which is fine.

## 2. Generate, build, run

```
tos-recomp/scripts/regen.sh      # recompiler -> generated C++ (66 MB, not committed) -> tos_boot
tos-recomp/scripts/run.sh 30     # 30 seconds, opens a window
```

`regen.sh` takes about a minute on 16 cores. A window opens on your desktop.

## 3. Symbols

`symbols/GQSF.csv` maps SDK function names to addresses and is what makes the recompiler emit named functions with native replacements. It is regenerated by `tools/sdk-identify` (see its README) from two reference games' decompilation symbol maps (Wind Waker PAL and Twilight Princess PAL, both CC0) plus `symbols/GQSF.manual.csv`, names set by hand with their evidence. `symbols/GQSF.extra_funcs.txt` lists function entries that are only reached through pointers.

A function that has a name gets, at its entry, a check for a native replacement (`lookup_os_func` in `gcrecomp/src/os/`). Adding a replacement means adding a name to one of the tables there and making sure the address is named in the CSV.

## 3b. Merging SDK names

Binding a name makes the recompiler emit `lookup_os_func(name)` at the function entry: a gcrecomp HLE of that name REPLACES the recompiled SDK function, so a wrong name, or an HLE written for another SDK data layout, breaks the game. `scripts/merge-sdk-names.py` lists, for every change, whether the name has an HLE (parsed from the lookup tables in `gcrecomp/src/os`). Merge in groups, regenerate with `scripts/try-symbols.sh` after each, and keep a group only if the new-game script still reaches the classroom with the same timeline (`wait 800` at about frame 6740, `[gp]` about 7100 frames at 190 s). Names without an HLE are only labels (readable traces, `GCRECOMP_TRACE_*`). Names that are known to break are in `docs/sdk-names.md` and are passed to `--exclude`.

## 4. Finding out where the game is stuck

- The watchdog in `src/main.cpp` prints, when `run.sh` ends, the last indirect dispatch, the per-function counts of replaced calls (`[hle]`), and GP statistics (`[gp]`). Counts in the tens of millions point at a polling loop.
- `[FuncTable] Unresolved call to 0x...` means an indirect call to an address that is not a function entry (typically a callback built with `lis`/`addi`): run `scripts/add-unresolved.sh run.log` (it appends the addresses to `symbols/GQSF.extra_funcs.txt`; `--dry-run` only lists them), review them, then `regen.sh`.
- Attach `gdb` to the running process (`gdb -p PID -batch -ex "thread 1" -ex "bt 20"`). Generated functions are named `func_XXXXXXXX`, replaced SDK functions by their SDK name.

## 4b. Debugging tools (reusable, keep them)

Nothing used to debug the game should be a throwaway: add it under `scripts/` (or to `common`/`tools`/`gcrecomp` if it is general), with `--help`, arguments instead of hard-coded paths, and a line here.

| Tool | Use |
| --- | --- |
| `scripts/guest-gdb.sh --break func_8016EF28 --args "r3 r4" --mem 0x80359940:4 --bt 6 --ignore 20000` | Breakpoints on guest functions of the running game: prints guest registers and RAM words (decoded from the harness calling convention, no debug info needed) and the guest call chain. |
| `scripts/contact-sheet.sh <frames-dir> out.png --count 6` | One picture from a whole run: works on `TOS_SCREENSHOT_DIR` PPM files and on Dolphin's frame dump, to compare a run with the reference. Keep the output out of git. |
| `scripts/play.sh [--session NAME]` | Play by hand: persistent memory card, log, per-second performance line (`GCRECOMP_BENCH`) and a periodic screenshot under `~/.local/share/tos-recomp/<session>/`, so a tester can report a problem by giving the session name. Keyboard controls are listed in the script's header. |
| `fepor-recomp/tools/dolphin-run.sh` (owner's other project) | Runs the disc in Dolphin with scripted input and a frame dump, to get the reference frames. |
| `scripts/merge-sdk-names.py --v2 tools/sdk-identify/results/GQSF.v2.csv --dry-run [--groups os,dvd,...] [--exclude A,B] [--evidence X.new.tsv --markdown t.md]` | Merges an sdk-identify result into `symbols/GQSF.csv` (new / renamed / moved-start names, in groups) and reports which names are bound to a gcrecomp HLE (see "Merging SDK names"). |
| `scripts/try-symbols.sh --csv C --work /var/tmp/x --dol main.dol --files DIR [--seconds 190]` | Regenerates the code from a CSV into its own work directory (the shared `generated/` is untouched), builds `tos_boot` there (`-j4`, nice), runs the new-game input script and writes `summary.txt` (script markers, `[hle]` counts, `[gp]` frames). Delete the work dir afterwards. |
| `scripts/dol-disasm.py main.dol --range A:B` / `--callers ADDR` | Disassembles a DOL range and lists the direct callers of an address with the instructions that set r3-r5 (to tell `OSReport(fmt, ...)` from `OSPanic(file, line, msg, ...)`). Needs `capstone`. |

The runtime's own diagnostics are environment variables, listed in `scripts/run.sh` (`TOS_SCRIPT`, `TOS_SCREENSHOT_DIR`, `GP_TRACE`, `GP_DUMP_TEX`, ...).

## 5. Conventions

- English for code, commits, issues. GPL v3 for this repository, MIT for the `gcrecomp` fork. Sign every commit (`git commit -s`): a CI check enforces it.
- Never commit game data, extracted files, generated code, or pictures of the game.
- Do not read or copy code from projects under non-commercial licenses (PolyForm Noncommercial, for example `snesrecomp`).
